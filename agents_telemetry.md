# Контроль работы агентов (UNDER CONSTRUCTION)

Для просмотра выполняемых запросов к модели, можно использовать plug-in [opencode-llm-capture](https://github.com/aixmoyu/opencode-llm-capture)

Рекомендуется следовать [online-инструкции](https://github.com/aixmoyu/opencode-llm-capture/blob/main/INSTALL.md)

В случае Windows, необходимо скачать plugin в папку `%USERPROFILE%\.config\opencode\opencode-llm-capture`.

Процедура инсталляции размещает файл "llm-capture.ts" в папке "C:\Users\[пользователь]\.config\opencode\plugins\llm-capture.ts" и создаёт символическую ссылку на этот файл в папке "C:\Users\[пользователь]\.config\opencode\opencode-llm-capture\llm-capture.ts".

Проверить, если ли символическая ссылка в папке можно командой PowerShell:

```shell
Get-Item "$env:USERPROFILE\.config\opencode\plugins\llm-capture.ts"
```

Удалить символическую ссылку можно через Command Prompt:

```shell
del "%USERPROFILE%\.config\opencode\plugins\llm-capture.ts"
```

Получена ошибка "несовместимый плагин":

```
Server plugin error
Plugin: ~/.config/opencode/plugins/llm-capture.ts
Status: failed
Runtime: server
Source: ~/.config/opencode/plugins/llm-capture.ts
Error: Plugin must export a default definition with an id and an effect or setup function.
Reference: err_33cd541b
```

Модель предложила исправить ошибку и нашла решение, но, посколько выполнялась модификация глобального "package.json" я не стал эту модификацию применять. Потребовалось бы вычистить глобальную папку с зависимостями Node.js и переустановить OpenCode.

## Что передаёт агент на сервер

- Роль ассистента-разработчика
- Правила модификации кода: не удалять несвязанный код, сохранять стиль форматирования, отступы и комментарии
- Инструкции по безопасности и работе с файловой системой
- Схема доступных инструментов (Tools / Function Calling)
- Пользовательский запрос (User Message)
- Метаданные окружения и репозитория
- Структура проекта (дерево каталогов верхнего уровня или список ключевых файлов)
- Рабочая директория и используемый язык программирования / стек

Содержимое файла:

- Если файл подгружается сразу (Pre-fetching): плагин/утилита определяет по тексту путь к файлу XXX, считывает его с диска и включает в контекст целиком (или с нумерацией строк), оборачивая в специальные маркеры (например, <file path="XXX">...код файла...</file>)
- Если используется агентный подход (ReAct): сначала модель получает только ваш запрос и описание инструментов. Модель принимает решение вызвать инструмент read_file("XXX"), среда выполнения считывает файл и отправляет его содержимое модели вторым шагом как результат вызова функции (tool_result)

## Что делает провайдер доступа к модели

Обеспечивает обезличивание запроса, таким образом, чтобы запрос нельзя было бы связать с учётной записью конкретного потребителя услуг.

## AI-скептицизм в разрезе инфобеза

Сложно не согласиться с тем, что использование облачных сервисов для инференса больших языковых моделей требует выгрузки некоторого количества данных в систему провайдера. Однако, кажется, что это не принципиально меняет поверхность атаки. В современных приложениях очень много исходных текстов доступны из браузера, обычным пользователям. Чаще всего - весь Frontend доступен обычному пользователю для анализа. В случае использования Vanilla JavaScript, анализ выполнять достаточно легко.

В случае, если собранные исходные тексты передаются заказчикам через системы обмена файлами, возможна декомпиляция бинарных сборок в исходные тексты приложения. Проще всего такую декомпиляцию сделать для сред исполнения с промежуточным представлением приложения в байт-коде. Т.е. проще всего  сделать декомпиляцию приложений написанных на .NET и Java. Однако подобные возможности существуют и для компилируемых в машинных код приложений.

## Сбор телеметрии в виртуальной машине с Linux

Поскольку сбор телеметрии требует установки дополнительных пакетов из непроверенных источников информации, кажется разумным использовать изолированную среду, например, виртуальную машину на Ubuntu 26.04.

Предварительная подготовка:

```shell
sudo apt install curl
```

Установка OpenCode:

```shell
curl -fsSL https://opencode.ai/v2/install | bash
```

Скрипт добавляет путь к OpenCode в переменные окружения, изменяя `/home/developer/.bashrc`. Перед первым запуском необходимо перезагрузить shell.

### Настройка API-ключа

Один из рекомендуемых способов хранения ключа - в отдельной папке "~/.secrets", в файле с доступом только у текущего пользователя:

```shell
mkdir -p ~/.secrets
echo -n "sk-JnD...6g9inM" > ~/.secrets/zvenoai-key
chmod 600 ~/.secrets/zvenoai-key
```

Соответственно, в "opencode.json" нам достаточно указать имя файла с ключом:

```shell
"apiKey": "{file:~/.secrets/zvenoai-key}"
```

### Добавление телеметрии 

Типовой способ установки утилиты **opencode-llm-capture** для сохранения телеметрии на диске:

```shell
git clone https://github.com/aixmoyu/opencode-llm-capture.git /tmp/opencode-llm-capture
mkdir -p ~/.config/opencode/plugins
cp /tmp/opencode-llm-capture/llm-capture.ts ~/.config/opencode/plugins/
rm -rf /tmp/opencode-llm-capture
```

При первом запуске plugin `~/.config/opencode/plugins/llm-capture.ts` не запустился. 

Посмотреть логи OpenCode можно командой:

```shell
sudo cat ~/.local/share/opencode/log/opencode.log
```

Причина сбоя была в том, что код приложения был написан для обеспечения работы с использованием "OpenCode V1 plugin API", а OpenCode версии 2.3.2 использует V2, с другой схемой.

Агент самостоятельно исправил ошибки, plug-in заработал.

Для того, чтобы сбор телеметрии начался, необходимо установить переменную окружения `OPENCODE_LLM_CAPTURE`:

```shell
export OPENCODE_LLM_CAPTURE=1
```

Проверка установленных переменных окружения:

```shell
env
```

Тестовый запрос для получения телеметрии, на примере работы с кодом проекта **SberXFS4Linux**: 

```
Analize @source/SBER.XFS3/examples/SIU.DORS.OPI4/HW/siu_adm.cpp
The code looks like really low-level. How could it be fixed to more concise and simplicity.
```


Логи сохраняются в папку `~/.config/opencode/opencode-llm-capture/llm-dump/`, но по факту, в единственном файле "latest-plugin.json" хранится лишь указание на папку, к которой осуществлялся доступ в последний момент времени:

```shell
{
  "timestamp": "2026-11-21T16:21:52.902Z",
  "directory": "/home/developer/projects/SberXFS4Linux"
}
```

Проблема состоит в том, что сервис OpenCode уже запущен и он оперирует ранее доступными переменными окружения. Чтобы актуализировать флаги следует использовать команду:

```shell
export OPENCODE_LLM_CAPTURE=1
opencode service stop && opencode service start
```

Или, что ещё проще, передать переменную окружения напрямую сервису:

```shell
OPENCODE_LLM_CAPTURE=1 opencode --standalone
```

Но этого оказалось не достаточно - модель переписала "llm-capture.ts", чтобы обеспечить совместимость с *V2 native HTTP hooks*. После модификации кода, захват dump-ов заработал - дампы начала формироваться в подкаталогах `~/.config/opencode/opencode-llm-capture/llm-dump/`.

### Ключевые выводы

- Чувствительные данные необходимо переносить в секретные внешние папки
- В переменных окружения следует размещать только настройки режимов работы, но не логины/пароли
- Инструменты могут выгружать файлы с исходными текстами целиком, но в целом модель стремиться минимизировать объём передаваемых данных, т.к. объём критически влияет на качество работы модели. Контекст стоит дорого, при превышении контекста его приходится упаковывать, что приводит к потере данных и галлюцинациям
